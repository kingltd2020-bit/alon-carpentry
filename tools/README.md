# tools/

שני קובצי בדיקה. יחד הם מכסים את שני מסלולי הטופס:
`check.js` את מה שקורה כשהשליחה נכשלת, `check-success.js` את מה
שקורה כשהיא מצליחה.

**שניהם מחליפים את `fetch`** — האחד בכישלון מזויף, השני בתשובת 200
מזויפת. מאז ש-`WEBHOOK_URL` מולא בכתובת חיה זו לא נוחות אלא הכרח:
בלי ההחלפה כל הרצה של הבדיקות הייתה שולחת ליד אמיתי ל-n8n, מייצרת
שורה בגיליון ושולחת מייל.

> אף אחת מההרצות כאן לא פונה לרשת. אפשר להריץ אותן כמה שרוצים.

## הבאג שהבדיקה תפסה

מלכודת הספאם הוסתרה ב-`left:-9999px` — הטריק הסטנדרטי.
**ב-RTL זה נשבר.** כיוון הגלילה הפוך, ואלמנט שמוזז 9999px שמאלה
יוצר גלילה אופקית בכל הדף:

```
FAIL no-h-overflow [10319>320]
```

10,319 פיקסל רוחב גלילה במסך של 320. בטלפון זה מרגיש כמו דף שבור.
התיקון: `clip-path: inset(50%)` — מסתיר בלי לייצר overflow.

זה בדיוק סוג הדבר שלא רואים בעין ורואים במדידה.

## איך מריצים

צריך כרום. הסקריפט נדחף לתוך עותק של הדף, והתוצאות יוצאות ב-`<title>`:

```bash
cat index.html > t.html
echo '<script>' >> t.html && cat tools/check.js >> t.html && echo '</script>' >> t.html
chrome --headless --disable-gpu --virtual-time-budget=8000 --window-size=390,900 \
       --dump-dom "file:///$PWD/t.html" | grep -o '<title>RESULTS[^<]*'
rm t.html
```

**הערה:** `--screenshot` של chrome-headless-shell מחזיר במכונה הזו תמונה
ריקה בלי טקסט. המדידות דרך `--dump-dom` עובדות, ולצורך אימות פריסה הן
ממילא אמינות יותר מצילום מסך.

## check-success.js — מסלול ההצלחה

11 בדיקות. מחליף את `fetch` בתשובת 200 מזויפת ובודק שני דברים:

**מה נשלח ל-n8n** — `POST`, `Content-Type: application/json`, וב-payload
כל ארבעת שדות הטופס, `company` (בלעדיו n8n לא יכול לסנן בוטים)
ו-`sentAt` תקין.

**מה הדף עושה אחרי** — הודעת "קיבלתי" מוצגת, הודעת השגיאה לא,
הטופס מתרוקן (רק בהצלחה), והכפתור חוזר לעצמו.

`fetch` מוחלף אחרי `load` ולא לפניו — הוא נקרא בתוך המטפל בשליחה,
לא בטעינת הדף.

### הרצה

```bash
cat index.html > s.html
echo '<script>' >> s.html && cat tools/check-success.js >> s.html && echo '</script>' >> s.html
chrome --headless --disable-gpu --virtual-time-budget=8000 --window-size=390,900        --dump-dom "file:///$PWD/s.html" | grep -o '<title>RESULTS[^<]*'
rm s.html
```

בעבר צריך היה קודם להחליף ב-`sed` את `WEBHOOK_URL` בערך דמה, אחרת
הקוד נפל לענף השגיאה לפני שהגיע ל-`fetch`. עכשיו הכתובת מולאה
והשלב הזה מיותר.

**מה זה לא בודק:** שום דבר בצד n8n. ה-`fetch` מזויף, אין קריאת רשת
אמיתית, ואף מייל לא נשלח. את הצד השני בודקים לפי הטבלה בסוף
[`../docs/n8n-setup.md`](../docs/n8n-setup.md).
